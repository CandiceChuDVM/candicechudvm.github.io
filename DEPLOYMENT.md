# Deployment

No framework, no package dependencies. Node 20+ is the only requirement.

## Local build

```bash
node _build/build.mjs        # _data/*.json -> HTML at repo root
node _build/validate.mjs     # exit 1 blocks deployment
python3 -m http.server 8000  # then open http://localhost:8000
```

`build.mjs --check` builds in memory and fails if the committed HTML differs from what the
data produces. CI runs it to catch hand-edited HTML.

## Branches

| Branch | Role |
| --- | --- |
| `main` | Production. Every push deploys to https://candicechudvm.com |
| `preview/*` | Pull-request branches. Build + validate run; no deployment. |

## Pipeline

`.github/workflows/build-and-deploy.yml`

1. Checkout, set up Node 20.
2. `node _build/build.mjs --check` — fails if committed HTML is stale or hand-edited.
3. `node _build/validate.mjs` — SEO, accessibility, link, data-integrity and funding-privacy
   checks. Any error fails the run.
4. On `main` only: upload the repo as a Pages artifact and deploy.

A pull request that fails step 2 or 3 cannot be merged. Nothing reaches production without
passing both.

## When to deploy directly to main

Acceptable: a news item, a new talk or publication entry, a typo, a date correction, a link fix.

Use a pull request for: biography, funding, research project pages, the AI Education
curriculum, Home page structure, anything involving a sponsor logo, and anything where a
number is being published for the first time.

## Rollback

```bash
git revert <sha> && git push origin main    # preferred: keeps history
```

The deploy is a full static upload, so reverting the commit and pushing restores the previous
site on the next run (about a minute). If the site is actively broken, re-run the last known
good workflow from the Actions tab instead — that redeploys the previous artifact immediately
without touching git.

## Failure playbook

| Symptom | Cause | Fix |
| --- | --- | --- |
| `Committed output is stale` | Someone edited HTML directly, or `_data` changed without a rebuild | `node _build/build.mjs`, commit the result |
| `broken local link → x.html` | A `_data` link points at a page that no longer exists | Fix the link, or add a redirect in `site.redirects` |
| `field "amount" is not allowed` | Funding privacy contract violated | Remove the field; see `AGENTS.md` §4 |
| `contains a placeholder marker` | `TODO`/`TBD` reached rendered output | Fill it in or set `publish: false` |
| `canonical is not on candicechudvm.com` | `seo.baseUrl` changed | Restore it in `_data/site.json` |
| Deploy succeeds, site unchanged | Pages cache | Hard-reload; confirm the Actions run targeted `main` |

## Adding a new page

1. `_data/<page>.json` with `metaTitle`, `metaDescription`, `h1`, and content.
2. A `render<Page>()` function in `_build/render.mjs`, registered in `buildAll()`.
3. Add the filename to `PAGES` in `_build/validate.mjs`.
4. Add it to `nav` in `_data/site.json` if it belongs in the main navigation.
5. Give it a keyword row in `SEO_GUIDE.md`.
6. Build, validate, commit.

## Analytics and the backstage page

Traffic numbers are opt-in and provider-agnostic. `_data/site.json` → `analytics.provider`
accepts `none` (default), `cloudflare`, `plausible`, `umami`, `goatcounter` or `ga4`; the
renderer emits that provider's snippet on every page and nothing at all while the value is
`none` or its id is blank.

| Provider | Cost | Cookies | Shows countries | Embeddable in backstage |
| --- | --- | --- | --- | --- |
| `cloudflare` | free | no | yes | no |
| `goatcounter` | free (non-commercial) | no | yes | yes |
| `plausible` | paid | no | yes | yes |
| `umami` | free self-hosted | no | yes | yes |
| `ga4` | free | **yes** | yes | no |

Recommended: `cloudflare`. Sign in at dash.cloudflare.com → Web Analytics → add
`candicechudvm.com`, copy the beacon token into `analytics.cloudflareToken`, set
`provider: "cloudflare"`, rebuild, push.

`backstage.html` is a private operations page: dashboard links, analytics status, a setup
checklist, and an optional embedded dashboard (`_data/backstage.json` → `embed.url`). It is
`noindex, nofollow`, absent from `sitemap.xml`, absent from `nav`, and linked from no page —
reachable only by typing the URL. It is not password-protected, because GitHub Pages serves
static files with no authentication; keep nothing confidential on it. If real access control
is ever needed, the site has to move behind Cloudflare Access or an equivalent.

## Domain and DNS

GitHub Pages with a custom domain. If `candicechudvm.com` stops resolving, check that the
`CNAME` file still exists at the repo root — a build that overwrites the root can remove it,
and Pages then falls back to the `github.io` URL. `CNAME` is not generated by `build.mjs`
and must never be deleted.
